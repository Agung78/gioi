# Unauthenticated Nuxt development server exposes application source and Vite internals

**ID:** vuln-0002
**Severity:** MEDIUM
**Found:** 2026-11-10 01:13:00 UTC
**Target:** http://host.docker.internal:3002
**Endpoint:** /_nuxt/composables/useApi.ts
**Method:** GET
**CWE:** CWE-200
**CVSS:** 5.3
**Confidence:** High
**Fix Effort:** Low

## Description

The frontend on `http://host.docker.internal:3002` is running in Nuxt development mode and serves application source modules and Vite development assets to unauthenticated clients. Attackers can retrieve route, authentication, API, and business-logic source code, along with absolute developer filesystem paths.

## Evidence

Unauthenticated responses captured from the frontend include:

```http
GET / HTTP/1.1
Host: host.docker.internal:3002

HTTP/1.1 200 OK
x-powered-by: Nuxt
content-type: text/html;charset=utf-8
```

The HTML contains absolute source paths and a Vite runtime reference:

```html
<link rel="stylesheet" href="/_nuxt/@fs/Users/heyrcg/Documents/Works/gioi/apps/web/...">
<script type="module" src="/_nuxt/@vite/client"></script>
<script>window.__NUXT__.config={public:{apiBase:"https://gioi-api.vercel.app",...}}</script>
```

Direct unauthenticated source retrieval succeeds:

```http
GET /_nuxt/composables/useApi.ts HTTP/1.1
Host: host.docker.internal:3002

HTTP/1.1 200 OK
content-type: application/javascript

... apiFetch("/staff/me") ...
... apiFetch("/admin/audit-log") ...
```

`/_nuxt/stores/auth.ts` also returns `200`, while `/_nuxt/@vite/client` returns approximately 180 KB of Vite development runtime.

## Impact

An unauthenticated remote attacker can download internal frontend source such as `composables/useApi.ts` and `stores/auth.ts`, enumerate privileged API operations and client-side authorization assumptions, and retrieve the Vite runtime. The disclosure materially lowers the effort required to target the separate API, identify hidden administrative workflows, and chain authorization or object-access weaknesses. Absolute local paths and dependency versions also disclose deployment details.

## Counterevidence

Some frontend JavaScript is necessarily delivered to every browser, and the exposed modules do not themselves contain a confirmed secret. However, the response is not a normal production bundle: it serves raw TypeScript/Vue modules, Vite HMR runtime code, absolute developer paths, and internal source files directly. No authentication, reverse-proxy restriction, or production-build control was observed on the tested paths.

## What Would Change This Severity

Confirmation that the same development server is internet-reachable or contains source-level secrets would raise the impact; restricting port 3002 to a trusted development network and serving only a production build would lower it.

## Technical Analysis

The root response identifies a Nuxt development runtime (`x-powered-by: Nuxt`) and embeds module URLs under `/_nuxt/@fs/...` that expose the developer filesystem. The server also exposes `/_nuxt/@vite/client` and accepts direct requests for source modules, including `/_nuxt/composables/useApi.ts` and `/_nuxt/stores/auth.ts`, without authentication. The returned source contains the staff/admin API map and client authentication logic, which should not be available from a production deployment.

## Proof of Concept

1. Send an unauthenticated `GET` request to `/` on port `3002`.
2. Observe a `200` Nuxt development HTML response containing absolute `/Users/.../apps/web` paths and a `/_nuxt/@vite/client` module.
3. Send an unauthenticated `GET` request to `/_nuxt/composables/useApi.ts`.
4. Observe a `200` response containing readable application source and staff/admin API paths.
5. Send an unauthenticated `GET` request to `/_nuxt/stores/auth.ts` to retrieve authentication-store source as an additional control.

```python
import requests

base = "http://host.docker.internal:3002"
for path in ("/", "/_nuxt/composables/useApi.ts", "/_nuxt/stores/auth.ts", "/_nuxt/@vite/client"):
    response = requests.get(base + path, timeout=10)
    print(path, response.status_code, len(response.content), response.headers.get("content-type"))
    if path.endswith("useApi.ts"):
        print("staff endpoint disclosed:", "/staff/" in response.text)
        print("admin endpoint disclosed:", "/admin/" in response.text)
```

## Remediation

Run the Nuxt frontend in a production build (`nuxt build` followed by the production server) for any exposed environment. Bind the Vite/Nuxt development server only to a local interface or a protected development network, and require authentication at the reverse proxy if development access is unavoidable. Disable public access to Vite source modules, `@fs` paths, `@vite/client`, source maps, and HMR endpoints. Review deployment automation so `dev` mode cannot be started in production.

## Assumptions

The frontend is reachable by an attacker who can connect to port `3002`; no authentication or network restriction is applied before these asset requests.
