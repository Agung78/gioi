## 🔴 Critical — Must Fix

### 1. Missing FK Indexes
PostgreSQL does **not** auto-index FK columns. Every FK needs an index for JOIN performance and to avoid full-table locks on parent DELETE.

Required indexes (non-exhaustive):
```sql
CREATE INDEX idx_reservations_venue_id ON reservations(venue_id);
CREATE INDEX idx_reservations_guest_id ON reservations(guest_id);
CREATE INDEX idx_reservations_seating_area_id ON reservations(seating_area_id);
CREATE INDEX idx_guests_venue_id ON guests(venue_id);
CREATE INDEX idx_seating_areas_venue_id ON seating_areas(venue_id);
CREATE INDEX idx_feedback_venue_id ON feedback(venue_id);
CREATE INDEX idx_feedback_reservation_id ON feedback(reservation_id);
CREATE INDEX idx_reservation_status_events_reservation_id ON reservation_status_events(reservation_id);
CREATE INDEX idx_user_venues_user_id ON user_venues(user_id);
CREATE INDEX idx_user_venues_venue_id ON user_venues(venue_id);
CREATE INDEX idx_sessions_user_id ON sessions(user_id);
CREATE INDEX idx_audit_events_venue_id ON audit_events(venue_id);
CREATE INDEX idx_audit_events_actor_user_id ON audit_events(actor_user_id);
-- ...every FK column
```

### 2. Missing CHECK Constraints
```sql
-- feedback
ALTER TABLE feedback ADD CHECK (rating BETWEEN 1 AND 5);

-- reservations
ALTER TABLE reservations ADD CHECK (party_size > 0);

-- seating_areas
ALTER TABLE seating_areas ADD CHECK (capacity > 0);
ALTER TABLE seating_areas ADD CHECK (min_party > 0 AND max_party >= min_party);

-- venues
ALTER TABLE venues ADD CHECK (booking_interval_minutes > 0);
ALTER TABLE venues ADD CHECK (party_min > 0 AND party_max >= party_min);
ALTER TABLE venues ADD CHECK (lead_time_minutes >= 0);
ALTER TABLE venues ADD CHECK (cutoff_minutes >= 0);
ALTER TABLE venues ADD CHECK (no_show_target_percent BETWEEN 0 AND 100);
ALTER TABLE venues ADD CHECK (over_capacity_alert_percent BETWEEN 0 AND 100);

-- opening_hours
ALTER TABLE opening_hours ADD CHECK (weekday BETWEEN 0 AND 6);
ALTER TABLE opening_hours ADD CHECK (open_minute >= 0 AND open_minute < 1440);
ALTER TABLE opening_hours ADD CHECK (close_minute > open_minute AND close_minute <= 1440);

-- guests
ALTER TABLE guests ADD CHECK (phone ~ '^\+[1-9]\d{1,14}$');  -- E.164
ALTER TABLE guests ADD CHECK (length(email) <= 254);
```

### 3. UUIDv4 Fragmentation
Current: `uuid` (assumed `gen_random_uuid()` → v4 random) → B-tree fragmentation.
Fix: Use UUIDv7 (time-ordered).

```sql
-- PG18+
id uuid DEFAULT uuidv7() PRIMARY KEY

-- Older: pg_uuidv7 extension
CREATE EXTENSION IF NOT EXISTS pg_uuidv7;
id uuid DEFAULT uuidv7() PRIMARY KEY
```

## 🟡 Recommended — Before Scaling

### 4. Exclusion Constraint: Opening Hours Overlap
Prevent overlapping hours per venue per weekday.

```sql
CREATE EXTENSION IF NOT EXISTS btree_gist;

ALTER TABLE opening_hours
  ADD CONSTRAINT no_overlapping_hours
  EXCLUDE USING gist (
    venue_id WITH =,
    weekday WITH =,
    int4range(open_minute, close_minute) WITH &&
  );
```

### 5. Composite / Partial Indexes (after query patterns stabilize)
Likely patterns:
```sql
-- Reservations for venue in time range
CREATE INDEX idx_reservations_venue_time
  ON reservations(venue_id, starts_at);

-- Active reservations only
CREATE INDEX idx_reservations_active
  ON reservations(venue_id, starts_at)
  WHERE status IN ('confirmed', 'seated');

-- Non-anonymized guests
CREATE INDEX idx_guests_active
  ON guests(venue_id)
  WHERE anonymized_at IS NULL;
```

## 🟢 Nice-to-Have

### 6. Enum vs CHECK vs Lookup Table Audit
Custom types used: `reservation_channel`, `reservation_status`, `venue_role`, `actor_type`.

| Type | Current | Review |
|------|---------|--------|
| `reservation_status` | ENUM? | Stable → ENUM OK |
| `reservation_channel` | ENUM? | May grow → CHECK or lookup |
| `venue_role` | ENUM? | Small, stable → ENUM OK |
| `actor_type` | ENUM? | Fixed set → ENUM OK |

If ENUM: cannot remove values, need `ALTER TYPE` to add.

### 7. Virtual Generated Columns (PG18+)
```sql
-- Example: derived display field
booking_display text GENERATED ALWAYS AS (
  'RES-' || substring(booking_code FROM 1 FOR 8)
) VIRTUAL
```

## Re-evaluation Checklist

When re-evaluating, verify:

- [ ] All FK columns have indexes
- [ ] All domain CHECK constraints present
- [ ] UUIDv7 default on PKs
- [ ] Exclusion constraint on `opening_hours`
- [ ] Composite/partial indexes match actual query workload (via `EXPLAIN ANALYZE`)
- [ ] Enum choice reviewed per table above
- [ ] Generated columns considered for denormalized read paths
